# HOW TO RUN — EXPERIMENT_2

## Interpreter

Use **C:\Python313\python.exe** explicitly. The bare `python` on PATH is
Python 3.8 with nothing installed; 3.13 is the one carrying numpy, scipy,
scikit-learn 1.7.2, pyriemann 0.12 and matplotlib.

    C:\Python313\python.exe -c "import pyriemann, sklearn; print('ok')"

`requests` and `certifi` were installed for the download step (system Python
had no CA bundle, so https to the TU Graz mirror failed certificate
verification). If that ever breaks again:

    C:\Python313\python.exe -m pip install certifi requests

No MOABB and no MNE are needed. The BNCI .mat files are read directly with
scipy.io, which is why this folder has no heavy dependency chain.

## Order

    cd /d D:\trainsvm\EXPERIMENT_2

    C:\Python313\python.exe s01_fetch_2b.py        first run ~15 min, then ~90 s
    C:\Python313\python.exe s02_run_models.py      ~100 s on 16 cores
    C:\Python313\python.exe s03_report.py          ~5 s
    C:\Python313\python.exe s04_gelo_transfer.py   ~3 min (10,000 permutations)
    C:\Python313\python.exe s05_polarity_check.py  ~3 min
    C:\Python313\python.exe s06_calibration_curve.py  ~3 min
    C:\Python313\python.exe build_study_pdf.py     ~5 s  -> STUDY.pdf

The decoder itself is a separate, standalone module and needs none of the s0*
scripts except s01 (for the cached training data):

    C:\Python313\python.exe gelo_svm_pipeline.py train
    C:\Python313\python.exe gelo_svm_pipeline.py predict

build_study_pdf.py needs `reportlab`, already installed. The PDF embeds the
four figures from results\figures, so run s03 and s06 before building it.

s01 downloads 18 files, ~615 MB, into `data\`. It skips anything already
present, so re-running it only re-epochs. To force a fresh download, delete
the .mat files.

s00_diagnose_window.py is diagnostic only and is not part of the chain. Run it
if the accuracies ever collapse to chance again — it finds where in the trial
the laterality actually sits and will tell you immediately whether the window
is wrong. It needs the .mat files, so run it after s01 has downloaded.

## Reading the output

`results\summary.csv` — 56 rows, one per (protocol x artefact mode x model x
EA). Read `mean_bal`, not `mean_acc`; they coincide here because 2b is exactly
balanced, but the habit matters.

`results\per_subject.csv` — 504 rows, the same broken out per subject. This is
where to look before quoting any mean: the P2 spread is 0.567 to 0.942.

`results\figures\` — three PNGs, regenerated by s03.

## If you change something

* **Window or band**: `CUE_OFFSET`, `TMIN`, `TMAX`, `MAIN_BAND`, `FB_BANDS` at
  the top of s01. Changing any of them means re-running s01 (the covariances
  are cached, not recomputed by s02) and then s02.
* **Models or grids**: `build()` and `CGRID` in s02. s01 does not need to
  re-run.
* **A new dataset**: s02 only ever sees `data\sub-XXX.npz` with keys
  `cov`, `y`, `sess`, `art`. Anything that writes that format — including a
  Gelo exporter — drops straight into this pipeline with no change to s02.

## Things that will bite you

1. **The RNG is reseeded per configuration** (`np.random.seed(SEED)` at the
   top of `run_one`). This is deliberate: Experiment_svm had a bug where a
   variable named `rng` shadowed MATLAB's `rng()` and results depended on how
   the run was chunked. Do not remove the reseed.

2. **Euclidean Alignment is unsupervised and must stay that way.** It uses the
   session's mean covariance and no labels. If you ever make it label-aware,
   applying it to the test session becomes leakage and every number in the
   report becomes meaningless.

3. **Do not move CSP, tangent space or feature selection outside the
   Pipeline.** They are supervised. Fitting them once on all data and then
   cross-validating is the single most common way CSP results get inflated.

4. **LinearSVC, not SVC.** The cross-subject folds train on ~5,800 trials;
   libsvm's quadratic scaling makes that grid search take hours. If you swap
   it back, expect the runtime to go from 100 seconds to several hours for no
   measurable gain.
